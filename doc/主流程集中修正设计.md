# 主流程集中修正设计

2026-09-08。针对 `main-preintegration-review.md` 的一次集中问题包。范围为 V1.9 内存原型；不扩展公共服务、持久化或真实 CI。用户可见收益是来源变更及时阻断、原型编辑不留下假忙、自测控制故障可继续、交接保留真实历史。退出条件为定向反例和整体复核通过；若再出现结构性权威变化，停止补丁重新评估。

1. **上游权威**：9 份文档的正文/版本/定稿序号与 readiness（finalized、finalVer、modified、pendingCount）共同观察。readiness 不进入文档内容指纹，但进入治理快照；source audit 实时验证，生成/检查/定稿/开发均拒绝失效来源。规划允许生成带问题的诊断结果。旧回调只读比较完整快照，失配零写。
2. **原型写入**：保存、撤销、重做、版本切换、提交、接受/拒绝 pending、上传初稿和 AI pending 使用一个写事务。先确认项目、未定稿和动作可执行，再在同一 draft 作废 running operation（换 token、标 stale、记审计），随后写内容/readiness。失败恢复 S.proto 和设计状态；无操作不解锁。引用样本不改变工件身份。定稿解锁也经此入口；生成与定稿保留各自 operation 事务。
3. **自测恢复**：operation 保存派发的 action/targetId/stateIdentity/runToken。仅在当前父运行精确匹配时记录 SELFTEST_START_FAILED，并清除恰好属于失败 operation 的 lastDispatch；继续入口和按钮允许这类控制失败，仍完整重验授权/准备/输入/计划。质量失败继续要求实质返工，不作为控制失败自动重试。
4. **交接**：事务内再次验门禁。仅当非终态 run 的 authorizationId 对应当前 active auth，且 auth 的 planSnapshotId/inputFingerprint 对应本次报告时，结束该 run 并消费 auth。stopped/transferred 及无关 run/auth 原样保留。失败回滚整个交接；报告不改写。
5. **来源和界面证据**：source audit 保存从批准文档章节到目录目标的 forward，以及目录目标到实际章节的 reverse。计划深冻结这些事实及未核实项。selftest-status 展示当前结论，逐页逐视口的状态明细默认折叠并使用 selftest-state-* 入口。

反例矩阵：9 来源 × 4 readiness；原型全部写入口在定稿/检查中/无操作/审计失败下的结果；自测启动和完成故障、错误父身份、旧 dispatch、输入变化后恢复；当前、人工接管、已停止和无关运行的交接；来源双向完整性及 selftest 状态入口。已有 kernel/客户模板/build renderer 不在本修正写入范围。
