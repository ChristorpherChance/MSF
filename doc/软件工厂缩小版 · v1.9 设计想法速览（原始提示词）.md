# 软件工厂缩小版 · v1.9 设计想法速览（原始提示词）

> 状态：用户已确认开始修改。承接 v1.8，新增完整设计基线与开发自测。

## 1. 开发完成后应先自测

用户：开发阶段执行完后应接质量检查，主要是开发阶段的自我测试，包括单元测试、前后端联调等；正式测试前先自我审核，形成自测报告，合格后再转测试。

已确认：名称改为「开发自测」。单测和代码检查在开发过程中持续进行，开发完成后做整体联调、关键业务冒烟和汇总。AI 自动生成报告，必测用例通过、质量目标达标、没有阻断缺陷后，最后由人确认转测试。

→ 详见方案文档 §3、§4。

## 2. 功能与 UI 都必须达标

用户：除了功能测试通过，实际 UI 与前期 UI 原型设计也要有很高匹配度，才说明达成目标。

已确认：UI 符合度单独作为提测门槛；覆盖页面、布局与视觉、交互、关键状态及响应式。每页一般视觉检查项符合率建议至少 95%，关键项和必测覆盖 100%，严重偏差为 0。截图用于对照和定位，不以像素相似度冒充业务符合度。

→ 详见方案文档 §3。

## 3. 先把原型本身做完整

用户：设计阶段的原型 UI 目前不足，必须把客户需求覆盖到位，并与概要设计和详细设计对应。

已确认表述：**需求完整覆盖，设计双向可追溯，内容相互一致。** 三类设计共同覆盖全部需求；原型完整表达 UI 适用需求，其他需求由概要和详细设计承接。对应关系检查到具体角色、字段、规则、页面和状态，不只挂文档链接。

原型流程为「识别页面与流程 → 生成完整原型 → 检查需求覆盖与设计一致性 → 处理问题 → 确认定稿」。定稿形成版本组合与验收依据，后续任务识别和自测使用同一基线。

→ 详见方案文档 §1、§2。

## 4. 保持简单并允许人工参与

沿用前轮要求：使用者快速看见需本人处理的问题；AI 承担规划、核对、执行和汇总；保留人工操作与暂停接管。页面风格与之前阶段一致，不增加需要手工维护的复杂表格。

→ 详见方案文档 §5。
