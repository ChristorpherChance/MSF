# 测试验收闭环实施计划

> 使用 executing-plans 在当前会话串行实施；用户已批准按推荐方案制作可交互原型，不创建隔离代理。

**Goal:** 在根目录V1.9实现独立测试验收闭环。
**Architecture:** 新增测试维护源静态嵌入单HTML，测试业务数据保存在S.test.acceptance；只读消费开发交接，不覆盖旧证据。四页签共用批次、计划、运行、缺陷及报告身份。
**Tech Stack:** 原生JS/CSS、Playwright、Node；不新增外部依赖。
**Spec:** 测试验收闭环方案文档.md。

## Global Constraints
- 不改旧版本、开发公共状态契约、冻结客户模板和证书。
- 不自动提测、定稿、批准或生产发布；模拟执行明确标识。
- 不创建worktree或隔离代理；不commit/push/tag。
- 失败必须有可见原因，所有控制可交互；历史批次/报告不可变。
