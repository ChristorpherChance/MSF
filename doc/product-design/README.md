> 编写路线：以 `../msf-prototype.html`（V1.11）为事实源逆向产品行为，将全部模拟点替换为真实产品能力规格（路线 A）。

## 2. 编号规则

### 2.1 需求编号（PRD）

按域分段，追溯链为 **R（原始诉求）← CR（客户需求）← REQ（产品需求）← DSG（设计条目）**：

| 段 | 域 |
| --- | --- |
| R-xx | 原始诉求（CRD，尽量保留用户原话要点） |
| CR-xx | 客户需求条目（CRD，结构化后的需求陈述） |
| REQ-1xx | 资料库 |
| REQ-2xx | 需求管理（CRD/PRD/RTM） |
| REQ-3xx | 设计（HLD/LLD/原型/基线） |
| REQ-4xx | 开发（计划/执行/autopilot/自测/转测试） |
| REQ-5xx | 测试验收（批次/用例/缺陷/报告/交付） |
| REQ-6xx | AI 助手与多 Agent 编排 |
| REQ-7xx | 平台通用（项目/导航/通知/设置/审计） |
| REQ-8xx | 非功能需求 |
| BR-xx | 核心业务规则（跨域通用规则，独立编号） |

规则：
- 编号一旦分配**永不复用**；需求废止标 `已废止` 并保留原行，不删行、不改号。
- 新增需求取该域当前最大号 +1，不允许插队挤号。
- 需求正文可变（见 §5 变更管理），编号与所属域不可变。

### 2.2 设计编号（HLD/LLD）

- HLD 模块：`DSG-M01`、`DSG-M02`…
- LLD 各册前缀（沿用原型章节习惯）：模块 `M-`、流程 `F-`、类 `C-`、数据 `D-`、接口 `A-`、界面 `U-`、非功能 `N-`，条目形如 `DSG-F04-2`（流程册第 4 章第 2 条）。
- 章节段编号两位补零（示例 `DSG-F01-2`、`DSG-C01-1`），条目段不补零。
- 每个 DSG 条目必须反向引用至少一条 REQ/BR；无法引用的设计条目必须标注 `补充设计` 并说明理由。

### 2.3 原型出处标注

每条 REQ 标注原型出处，格式：`原型: <视图或机制> / <函数或契约条款>`，例如 `原型: stage-dev / commitDevAction`、`原型: 契约§5 写事务`。无原型出处的需求标注 `新增: <理由>`。

### 2.4 待澄清编号约定

各册「待澄清」表内条目编号统一为 `C-<n>`（册内递增、不复用）；跨册引用写「册名 C-<n>」（如「LLD-2 C-4」），不写裸编号。已裁决回销的条目移入 `统稿裁决记录.md`，原编号不再启用。

## 3. 追溯规则（双向）

1. **正向**：RTM 中每条 REQ/BR 至少映射到一个 DSG 条目或明确标注 `由非 UI/非设计途径承接`（如纯运营规则）。
2. **反向**：每个 DSG 条目必须能回到至少一条 REQ/BR；孤儿设计必须标 `补充设计` 并在 RTM 登记。
3. **覆盖判定**：追溯成立需要具体内容证据（章节号 + 摘要），不允许只挂编号。
4. RTM 同时登记每条需求的**原型出处**，使「需求 → 设计 → 原型行为」三方可互查。
5. RTM 是活文档：任何需求/设计变更提交时，同一次提交必须同步更新 RTM 相关行。

## 5. 变更管理规则（需求矩阵防错乱）

目的：需求或设计变更时**不遗漏、不错乱、可追溯**。本规则对用户提出的「需求变更矩阵」要求负责。

1. **变更入口唯一**：任何需求变更先改 `PRD.md` 对应条目（正文可改，编号不变），再同步设计册，最后更新 `RTM.md`；三者必须在**同一次提交**内完成。
2. **变更标注**：条目级维护 `修订记录`（日期、原因、影响面）。重大变更（规则语义改变）在条目尾追加一行：`变更: 2026-xx-xx 由<旧表述要点>改为<新表述要点>`。
3. **影响分析强制**：变更某条 REQ 时，必须在 RTM 中查出其全部下游 DSG 与上游出处，逐一确认「需改 / 不受影响」，结果记入该条修订记录。
4. **废止不删除**：废止条目打 `已废止` 标记并保留；其下游设计条目标注承接状态变化。禁止物理删除造成编号空洞歧义。
5. **新增不断号**：新增条目取域内最大号 +1；RTM 追加行，不重排既有行。
6. **版本基线**：文档体系每次评审通过形成基线（日期 + 全部文件 SHA-256 清单，登记在 RTM 尾部「基线记录」表）。基线之后的变更以条目修订记录体现，不悄悄改历史。
7. **一致性自检**：每次变更后执行 RTM 自检清单——(a) 每个 REQ 有下游承接或豁免说明；(b) 每个 DSG 有上游 REQ/BR；(c) 无悬空编号引用；(d) 无重复编号。
