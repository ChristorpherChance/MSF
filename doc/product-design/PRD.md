## 1. 产品定位与目标

### 1.1 定位

软件工厂（MSF）是一个 **AI 驱动的软件交付流水线平台**：把一个软件项目从「客户资料」到「验收交付」的全过程——资料解析、需求管理、设计（含 UI 原型）、开发、测试验收——组织为一条有门禁、有证据、可追溯的流水线。AI 承担规划、生成、核对、执行与汇总；**关键放行点永远由人确认**。

### 1.2 目标

1. 交付过程**全链路可追溯**：每条需求可追到设计与页面，每个交付结论可追到执行证据。
2. AI 深度执行但**不替人决策**：文档定稿、计划批准、转测试、放行，必须人工。
3. 质量结论**不可注水**：未执行/跳过不算通过；证据不可变、不可改写；输入变了旧结论自动失效。
4. 自托管部署，团队数据不出内网。

### 1.3 非目标（本期冻结）

- **生产环境发布**：本期不做，但架构必须预留发布适配接口（工件/报告/批次身份已具备交付形态），待整个项目完成并测试通过后作为扩展接入，届时不改写既有链路。
- **多用户协作与细粒度权限**：本期最简（本地账号、单写者纪律已足够），账号体系与 RBAC 作为后续扩展，数据模型与审计字段本期就按多用户设计（操作者字段不留空）。
- 不做多租户 SaaS；单节点自托管。
- 不做通用任意 HTML 语义理解；原型检查规则针对本平台生成的工件。
- 不替代正式测试团队与客户验收签字流程，本平台提供证据与流转支撑。

## 2. 角色与权限

### 2.1 用户角色（本期最简，预留扩展）

本期为**本地账号最简形态**：一个部署实例内默认单一工程师身份即可走通全流程，管理员能力（设置/密钥）以本地配置承载。完整账号体系与 RBAC（管理员/工程师/只读）为**后续扩展**（REQ-707），但本期所有数据与审计字段必须带操作者身份，不允许留空或硬编码——保证权限体系接入时无需重建数据。

原型为单机无鉴权；出处：`原型: settings / 新增: 自托管账号（后续扩展）`。

### 2.2 系统内虚拟执行者

AI 助手、子 Agent、autopilot 自动运行是平台内的**虚拟执行者**：其操作有独立身份（runId/token）与归属记录，与人工操作严格区分，审计可查（BR-08、BR-13）。

## 3. 产品范围

**包含**：资料库（含 ZIP 与批量加工）、需求管理（CRD/PRD/RTM）、设计（HLD + 七册 LLD + UI 原型与基线）、开发（计划/执行/autopilot/开发自测/转测试）、测试验收（批次/用例/缺陷/报告/交付决定）、全局 AI 助手、多 Agent 委派、项目与设置管理、审计。

**不包含**：生产发布、多租户、计费系统、移动端原生应用。

## 5. 核心业务规则（BR）

> 这些规则跨域通用，是本产品的灵魂，优先级全部为 P0。每条均可追溯到原型契约条款。

| 编号 | 规则 | 内容 | 原型出处 |
| --- | --- | --- | --- |
| BR-01 | 内容指纹身份 | 关键工件（文档版本/原型/基线/计划/构建/报告/批次）以规范化内容哈希为身份；内容变即身份变，引用方必须按指纹校验 | `契约§3 / devHash` |
| BR-02 | 双层指纹 | 治理输入指纹与内容指纹分离；readiness 类状态（待办数、修改标记）不进内容指纹——人工定稿不会让刚定的基线立即过期，但内容变化会 | `契约§3` |
| BR-03 | 不可变证据 | 定稿、基线、报告、批次、决定追加式不可变；历史不可改写；`currentXxxId` 只是指针，不是有效性证据 | `契约§2/§4` |
| BR-04 | 封闭命令与原子事务 | 写操作必须走封闭命令枚举：prepare（纯计算）→publish（原子替换）→flush（效果幂等）；**审计失败零写**——业务状态、界面、定时器都不变 | `契约§5 / preparePrototypeCommand` |
| BR-05 | 草稿与历史分离 | 已提交版本不可变、编号不复用；单一工作草稿；undo/redo 对称；发布前校验不变式（draft 与 modified 一致、历史逐版本字节等价、每次操作恰好追加 0 或 1 条）；已丢失的历史绝不重建或谎称修复 | `原型草稿与历史版本重设计` |
| BR-06 | 人工确认点（可自动化就绪） | 确认点全集 7 点：req.doc.finalize、design.prototype.finalize、dev.plan.approve、dev.transfer、test.plan.approve、test.report.finalize、test.release，默认由人执行；**每个确认点必须实现为可配置的策略门禁**（REQ-711）：条件、检查项与放行判定皆为结构化策略，成熟后可经人工授权切换为自动放行；AI 在「人工」策略下永不可替代 | `方案§2/§4` |
| BR-07 | 门禁与失效传播 | 任何上游输入变化使下游检查/基线/报告立即失效；过期证据不能放行新内容 | `契约§4.1 / devInvalidate` |
| BR-08 | 异步操作身份 | 异步操作以 operationId+token+action+owner 四元组为身份；回调提交前重验实时指纹与父运行身份；晚到/失效回调严格零写 | `契约§4.1` |
| BR-09 | 通过语义 | 关键项 100%、单页一般项 ≥95%、严重偏差 0；skipped/not-run/not-applicable 一律不计通过；分母不可缩小；不以平均掩盖单项不达标 | `V19_UI_ACCEPTANCE_RULES / ui-scoring` |
| BR-10 | 失败纪律 | 失败进入「需你处理」并定位；复测需实质变化；同一失败不能空转无限重跑；失败历史保留 | `契约§8-10` |
| BR-11 | 证据真实性 | 执行证据必须来自真实执行并可溯源；模拟必须显式标注；对照比较两侧不得渲染同一对象 | `方案§3` |
| BR-12 | 单一写者 | 同一工件同一时刻仅一个写者；并发写按服务端版本拒绝；批量作业前后快照比对 | `实施计划全局约束 / basis()` |

| BR-14 | 崩溃恢复 | 事务失败回滚；效果 ledger 逐条 pending→running→done/failed/stale，重启后幂等补记；恢复函数可重入 | `原型写事务重设计` |

## 7. 验收标准

### 7.1 本文档体系验收

1. PRD/HLD/LLD 七册/RTM 齐全，编号无重复、无悬空引用。
