**形态**：自托管单节点，Docker Compose 一键部署（app / postgres / minio / redis / sandbox-runner / egress-proxy 六服务）。承接 REQ-710。

> 注：横切服务「命令事务」运行时归属 M11（证据与审计服务）——审计失败零写要求命令与审计写入在同一事务，不单列模块号。

**核心架构思想**：原型中的全局内存态 `S` 在真实产品中分解为「服务端领域状态（Postgres）+ 不可变证据（追加表+对象存储）+ 客户端会话状态（SPA）」三层；原型的命令事务、指纹、门禁、效果恢复机制完整保留并上升为**后端横切服务**，是本平台区别于普通 CRUD 系统的骨架。

## 2. 技术选型

| 层 | 选型 | 理由 | 备选（未选原因） |
| --- | --- | --- | --- |
| 前端 | React 18 + TypeScript + Vite + Zustand | 原型交互重（看板/树/流式/多视图），React 生态与团队 JS 背景吻合；Zustand 承接原型单例 S 的心智模型；助手 dock 会话界面以 pi-web-ui 的 Lit 聊天组件为**参考实现（浅 fork + 裁剪依赖）**——pi-web-ui 版本滞后于 pi-* 锁步主线（0.75.3 vs 0.86.0）且依赖重，不可直接依赖，fork 后维护责任归平台；外观按平台设计令牌定制（REQ-615 扩展） | Vue（团队栈连续性弱于 React） |

| 部署 | Docker Compose 单节点 | 自托管、数据不出内网；K8s 为后续扩展 | K8s（本期过度工程） |

## 4. 关键架构决策（ADR 式）

### ADR-1：模块化单体，而非微服务
自托管单节点、团队规模有限，微服务的运维与分布式复杂度无对应收益。NestJS 模块边界 + 独立领域表 + 明确的模块接口保留未来拆分空间。承接 REQ-710、REQ-807。

### ADR-2：原型机制 → 真实架构的映射
| 原型机制 | 真实架构 |
| --- | --- |
| 全局内存 `S` | Postgres 领域表（权威）+ SPA 会话态（Zustand，刷新可重建） |
| `commitDevAction` / `DEV_ACTION_REGISTRY` | 命令事务服务：封闭命令枚举 + DB 事务 + 事件表（§5） |
| `preparePrototypeCommand/publish/flush` | 命令三阶段：应用服务纯计算 → 单事务落库 → 效果任务入队幂等执行 |
| FNV `devHash` | SHA-256 + 规范化序列化（key 排序、去时间戳），M11 统一实现 |
| 基线/报告/批次不可变 | 追加式证据表（禁 UPDATE/DELETE，DB 层约束）+ 对象存储内容寻址 |
| `V19_TEST_HOOKS` 故障注入 | 仅测试环境特性开关，生产构建剔除（REQ-805 配套） |
| 单 HTML iframe 预览 | 工件存 MinIO，预览经 sandboxed iframe + 独立子域，禁同源脚本 |
| `decideMock` 模拟决策 | M08 = Pi SDK 嵌入 + 平台强制层包裹；业务层只依赖编排层接口（REQ-614/615） |
| autopilot `devAutopilotTick` | BullMQ 编排工作流：步骤任务化、归属 token 校验、晚到回调零写 |

### ADR-3：命令事务是唯一的写路径（BR-04 落地）
所有领域写操作=封闭命令枚举中的一条命令，统一管线：`鉴权 → 幂等检查 → prepare（纯计算，无副作用）→ publish（单 DB 事务：业务写入+事件追加+审计追加，指纹复核）→ flush（效果任务入队，逐条 ledger 幂等）`。审计写入失败 → 整体回滚，界面不得显示成功（审计失败零写）。命令注册表按域分册维护（LLD-2）。

### ADR-4：双层指纹与失效传播（BR-01/02/07 落地）
工件身份 = `规范化内容 SHA-256`；治理输入指纹（上游版本组合）与内容指纹分离，readiness 类字段不进指纹。任何工件写入时，M11 计算并登记指纹；下游引用方存「被引用指纹」；查询门禁时实时比对，不一致即 stale，UI 明示失效原因与重新执行入口。

### ADR-5：不可变证据存储（BR-03 落地）
证据/报告/批次/决定/历史版本：`append-only` 表（DB 角色禁 UPDATE/DELETE 权限）+ 每条记录含前序记录哈希形成**哈希链**；大体积内容（HTML 工件、截图、导出文件）入 MinIO，key=内容哈希；表内仅存元数据+内容哈希引用。满足「历史不可改写、指针不是证据」。

### ADR-6：AI 编排层基于 Pi SDK（REQ-613/614/615 落地）
业务代码不直接调模型 SDK，AI 后台基础统一基于 Pi SDK（@earendil-works/pi-*）构建，按明确分层实现：
- **Pi 负责**：模型调用与多供应商接入（pi-ai：流式、工具调用、鉴权、token/成本计量）；agent loop、工具执行、turn/message 事件（pi-agent-core）；会话管理（SessionManager JSONL 会话树）、模型注册与会话内切换（ModelRegistry）、提示词扩展（pi-coding-agent 嵌入 SDK）。
- **平台层负责**：工具注册表中平台工具（AGENT_TOOLS）包装为 Pi AgentTool 后注入运行时；提示词版本化落库（每次生成记录提示词版本+输入指纹，可回滚）；计量汇总（Usage 附着于消息结果而非独立事件流——平台从消息结果提取 Usage 落库并汇总展示，REQ-612；自定义模型须提供 cost 元数据，缺失时由平台 price_table 兜底）；引用上下文装配与基线校验（REQ-114/115）；**AI 行为边界（BR-06/REQ-613）在平台层强制**——AI 通道在技术上无法触达定稿/放行接口的「人工」策略分支（编排层与策略引擎双重强制）。
- **与 Pi 设计哲学的关系**：Pi 采用「无审批 YOLO + 容器化隔离」哲学，即运行时内部不做逐次权限确认；本平台的策略门禁在平台层（M12 放行策略引擎）强制，不依赖 Pi 的审批机制——Pi 侧不做门禁判断，平台侧每个确认点（BR-06 七点）单独求值留痕。

### ADR-7：放行策略引擎（REQ-711 落地）
每个确认点（文档定稿/原型定稿/计划批准/转测试/报告放行）调用策略引擎求值：`策略 = {确认点, 模式: manual|auto, 自动放行的前置条件集}`。默认全部 manual。auto 模式下引擎执行前置条件检查（证据有效、BR-07/09 满足），通过才自动放行，逐次留痕；模式切换本身是 manual 命令且通知项目成员。保证「成熟后免人工」不需要改架构。

### ADR-8：沙箱执行与委派隔离（REQ-803 落地）
单测/构建/用户命令在一次性 Docker 容器执行：只读挂载依赖、写入限工作区、网络默认关闭（白名单代理例外）、CPU/内存/时长限额；委派适配器首选 **pi RPC 模式**（stdin/stdout JSONL，承载 pi_native 先导目标），另有本机 Claude Code/Codex CLI 等适配器，同样经沙箱或受控远程运行时，任务间隔离，产出经证据通道回传；沙箱容器化与 Pi 的容器隔离哲学一致（REQ-615）。

**单任务编码执行器（REQ-407 载体，REQ-615 扩展）**：开发任务循环的编码/修单测环节在沙箱容器内以**嵌入式 pi-coding-agent AgentSession** 承载——沙箱工作区即会话工作目录，Pi 内建 read/write/edit/bash 工具即沙箱工作区操作面，会话由 SessionManager 管理（自动压缩），模型经 AuthStorage/ModelRegistry 注入；平台侧不实现自有编码 agent loop，只封装会话生命周期、限额与证据收集。委派任务在远端/沙箱内同样以 pi-coding-agent 承载执行，回传经 RPC JSONL 事件流（turn/message/工具调用）映射为平台证据登记 M11。**边界**：命令事务、证据/审计、放行策略门禁、ZIP 安全、评分算法等平台自有机制不改用 Pi。

**沙箱出向与密钥注入（2026-09-20 评审裁决，REQ-803）**：沙箱网络默认关闭与「沙箱内嵌 AgentSession 必须出向调模型 API」的张力按如下方式消解——沙箱出向唯一通道为 `egress-proxy` 部署单元（§6），域名白名单 = 已配置模型供应商端点，非白名单出向一律拒绝；模型密钥平台侧保管（M10 CredentialVault 加密落库），会话级临时注入沙箱环境变量，不写盘、用后销毁。

**编排选型（2026-09-20 评审裁决）**：沙箱容器编排默认采用 **docker.sock 挂载**——sandbox-runner 经挂载的 Docker socket 在宿主拉起一次性任务容器；最小权限补偿：专用 builder 用户运行、只挂构建所需目录、短命容器即用即毁。**权衡**：rootless DinD（容器内嵌套 Docker 守护进程）隔离更强，但引入嵌套构建的性能与运维复杂度（镜像缓存、存储驱动、特权/嵌套限制），本期不采用，列为安全加固选项（威胁模型升级时再评估，LLD-7 N02-4 同引）。

### ADR-9：扩展点预留
- **生产发布（REQ-712）**：M10 定义 `ReleaseAdapter` 接口（消费「验收通过批次+证据包」），本期仅接口与数据形态，无实现。
- **多用户/RBAC（REQ-707）**：所有表带 `actor_id`，审计/指纹含操作者；M02 鉴权中间件本期放行本地默认身份，策略点已就位。

## 5. 数据流（主链路）

1. **资料→需求**：上传/ZIP → M03 校验入库（对象存储+元数据）→ 解析作业（队列）→ 定稿 → 引用门禁放行给 M08 作为生成上下文（REQ-114/115）。
2. **需求→设计**：CRD/PRD 版本提交/定稿（命令事务+指纹）→ RTM 健康度达标 → M05 建立设计目录 → 原型生成/检查 → 人工定稿为设计基线（指纹组合入证据表）。
3. **设计→开发**：M06 以有效基线为输入识别任务 → 计划人工批准 → autopilot 编排任务循环（沙箱单测/CI 适配/AI 评审/Git 合并，每步证据入 M11）→ 集成构建（工件入对象存储）。
4. **开发→测试**：开发自测四门（功能检查/联调与冒烟/UI 符合度/开发审核）逐页评分 → 报告（不可变）→ 人工确认转测试（策略引擎）→ M07 幂等接收为批次。
5. **测试验收**：计划批准 → 用例执行（证据附着）→ 缺陷闭环（返工触发新构建新批次）→ 报告定稿 → 条件放行/交付决定（策略引擎）→（预留）发布适配。

## 6. 部署与安全边界

- **部署单元**：`app`（后端+静态前端）、`postgres`、`minio`、`redis`、`sandbox-runner`、`egress-proxy`；单节点 Docker Compose；备份=PG dump + MinIO 版本化桶 + Pi 会话目录卷（REQ-708）——`app` 服务以卷挂载 Pi 会话目录（SessionManager JSONL 会话树），纳入备份策略；沙箱内会话声明为一次性，随容器销毁、产物经证据链回传，不入备份。`egress-proxy` 为**沙箱出向唯一通道**：域名白名单 = 已配置模型供应商端点——沙箱内嵌 AgentSession 与委派执行体的模型调用一律经此出向（REQ-803，LLD-7 N02-4）。
- **基镜像**：`app` 与 `sandbox-runner` 采用 `node:22.19.x-slim`（Node ≥22.19，Pi SDK 0.86.0 运行要求）；tag 锁定到补丁版本并 digest 锚定，升级走变更评审；沙箱任务镜像清单（基础镜像+预装工具链、版本锁定与变更裁决）见 LLD-1 DSG-M09-1。
- **边界**：浏览器↔app（HTTPS，鉴权会话）；app↔沙箱（无网络默认、限额）；沙箱↔外部（**仅经 egress-proxy 出向**，域名白名单=已配置模型供应商端点）；app↔外部（Git/CI/模型 API，出向白名单）；MinIO 不直接暴露浏览器（签名 URL 短时有效）。
- **密钥**：模型/Git 令牌加密落库（KMS 或主密钥环境变量），不出现在日志与证据正文；沙箱内嵌 AgentSession 所需模型密钥由平台侧保管，**会话级临时注入沙箱环境变量——不写盘、用后销毁**（REQ-803）。
- **预览隔离**：生成的客户工件 HTML 视为不可信内容：sandboxed iframe + 独立子域 + CSP，禁止访问平台会话。

## 8. 冻结与边界

本期不做：生产发布实现（仅接口）、多用户 RBAC（仅数据模型预留）、多租户、移动端原生、K8s 部署。冻结项的扩展不得要求改写既有模块接口（ADR-9）。
