## 总则

1. 本章各条为非功能**强制规则**；指标未达标视同需求未完成，纳入 PRD §7.2 产品验收。
2. 阈值分三类：**承诺值**（承接 REQ，验收门槛）；**建议值**（标注「建议」，待压测校准后可修订，修订走 README §5 变更流程）；**目标值**（体验/性能期望目标，受外部因素制约，不作为验收阻断门槛，但必须持续观测并记录分布，长期偏离须回归评审）。
3. 所有安全机制默认不信任前端校验：浏览器端校验仅为体验优化，服务端必须独立复验。

## N01 性能（DSG-N01）

### DSG-N01-1 常规页面交互响应
- 规则：非 AI 类页面操作（导航、列表、详情、看板流转、文档打开）服务端与前端协同保证交互响应达标；后端常规 API（不含 AI 调用、沙箱执行）P95 响应 <300ms，慢于此的接口必须登记为异步作业走队列。
- 指标/阈值：常规页面交互 P95 <1s（承诺值，REQ-801）；后端常规 API P95 <300ms（建议值）。
- 验证方式：【测】以容量假设（N08-1）数据量造数后跑性能脚本，对五阶段主页面逐一采样 P95；【审】审查慢查询/慢接口日志，确认无同步长任务混入交互路径。
- 承接：REQ-801、REQ-802。

### DSG-N01-2 AI 流式首 token
- 规则：AI 生成（文档/原型/助手回复）一律走 SSE 流式输出；首 token 延迟按模型档位分档设定目标（受模型与网络制约，不作为硬性阻断指标）；超过 10s 未出首 token 时 UI 必须显示等待状态并提供可取消入口。
- 指标/阈值：首 token 目标——本地小模型 ≤3s、云端大模型 ≤8s（目标值，REQ-801 分档口径）；平台链路开销 <500ms（承诺值）；>10s 必须有等待提示与停止控件（承诺值）。
- 验证方式：【测】以录制回放的模型桩测首 token 链路开销（平台侧 <500ms），并按模型档位实测真实模型记录分布；【审】审查 SSE 事件时间戳日志，核对停止后无残留半截状态（REQ-603）。
- 承接：REQ-801、REQ-603、REQ-202。

### DSG-N01-3 大列表分页
- 规则：一切可能超过单页规模的服务端列表（资料文件、任务、审计、事件、版本历史）强制服务端分页；禁止「一次返回全量」接口。游标或页码分页择一并全平台统一。
- 指标/阈值：分页默认值与上限以 LLD-5 §1.5 为权威（默认每页 20 条、单页上限 200 条，建议值），本册不另立数值；单项目 1000+ 资料文件、100+ 任务下列表接口 P95 不劣化（承接 REQ-802）。
- 验证方式：【测】按 REQ-802 规模造数，翻页至末页测响应时间与内存；【审】代码审查 API 层确认所有 list 接口带分页参数且有上限保护。
- 承接：REQ-801、REQ-802。

### DSG-N01-4 虚拟滚动与树懒加载
- 规则：前端一次性渲染行数超过阈值时必须虚拟滚动；资料双目录树按节点懒加载，勾选/半选状态在服务端分页数据上仍正确聚合。
- 指标/阈值：渲染行数阈值 200 行（建议值）；1000+ 节点目录树展开/勾选操作 <1s（承诺值，REQ-801）。
- 验证方式：【测】大数据量下用浏览器性能面板测帧率与长任务；【审】审查列表组件是否命中虚拟滚动实现，核对半选状态算法不依赖全量加载。
- 承接：REQ-801、REQ-802、REQ-106。

### DSG-N01-5 预览与下载走对象存储直链
- 规则：工件/报告/构建产物/证据截图等大体量内容，浏览器经**短时签名 URL 直连 MinIO** 下载或预览，不经后端转发；MinIO 不直接暴露公网路径，签名 URL 由后端按鉴权结果签发。
- 指标/阈值：签名 URL 有效期 ≤15 分钟（建议值）；预览加载不占用后端连接（架构约束）。
- 验证方式：【测】大工件（10MB 级 HTML）预览时观测后端无相应流量；【审】审查签发逻辑：有效期、内容哈希 key 绑定、越权访问他项目 URL 被拒。
- 承接：REQ-801、REQ-803、HLD §6。
- 回补（2026-10-10，差异登记条目 36）：部署形态二选一——MinIO 浏览器可达时维持直签（默认，行为不变）；公网部署 MinIO 仅绑回环（127.0.0.1）时，env `MSF_FILES_PROXY=1` 将全部签名直签切换为本进程流式代理 URL（`GET /api/v1/files?key&dl&ct`，query 传 key 避开 %2F 路径段规范化问题；key 校验非空/≤512/无 `..`；GET 无写副作用，/api 面受鉴权门覆盖，未授权 401）。本条「不经后端转发」的架构约束在该分支下以「同进程流式 pipe、不整读入内存」弱化承接，其余口径（有效期、key 绑定、越权拒绝）不变。

### DSG-N01-6 缓存策略
- 规则：内容寻址（key=SHA-256）的不可变对象使用 `Cache-Control: immutable` 长缓存；静态前端资源指纹文件名长缓存；草稿、列表、门禁状态等可变数据禁缓存或短 ETag 协商缓存；**证据与报告内容只允许按内容指纹寻址读取，禁止按可变指针缓存**。
- 指标/阈值：不可变对象缓存 1 年（建议值）；可变数据不得出现脏读导致的门禁误判（承诺值，BR-07）。
- 验证方式：【测】修改上游内容后验证下游页面读取到新指纹版本；【审】审查各响应 Cache-Control 头矩阵与本条一致性。
- 承接：REQ-801、BR-01、BR-03、BR-07。

### DSG-N01-7 批量作业削峰与隔离
- 规则：批量解析/批量加工/原型生成/集成构建等长任务一律入 BullMQ 队列执行；worker 并发数受控，交互 API 与队列 worker 资源隔离（进程或容器级），长任务不得拖垮交互响应。
- 指标/阈值：批量作业运行期间，交互 API P95 仍满足 DSG-N01-1（承诺值）；worker 并发默认 ≤4（建议值）。
- 验证方式：【测】并发触发批量解析+批量加工+构建，同时跑交互性能脚本；【审】审查队列并发配置与资源限制配置。
- 承接：REQ-801、REQ-802、REQ-110、REQ-111。

## N02 安全（DSG-N02）

### DSG-N02-1 鉴权会话（本期最简 + OIDC 预留）
- 规则：本期为本地账号最简形态（REQ-707）：服务端会话鉴权，会话凭证存 HttpOnly + Secure Cookie，**SameSite 策略以 LLD-5 §1.2 为权威：`SameSite=Lax` + 双提交 Token（`X-CSRF-Token`）**（兼容 SSE 与预览子域；2026-09-20 评审裁决，本册不另立口径），会话状态存 Redis；未认证请求仅可访问登录页与静态资源。鉴权中间件按「身份提供者」抽象设计，预留 OIDC/LDAP 接入点（HLD ADR-9），接入时不改写业务代码。所有请求上下文带 actorId，禁止匿名写操作。
- 指标/阈值：会话空闲超时 12h 滑动续期、绝对有效期 7d（建议值，待压测校准，统稿 D-22）；认证失败响应不区分「账号不存在/口令错误」。
- 验证方式：【测】无会话/过期会话访问受保护 API 一律 401；会话固定、注销后复用旧凭证的负向用例；【审】审查中间件覆盖所有路由（含 SSE 端点），确认 actorId 注入链路无旁路。
- 承接：REQ-803、REQ-707、REQ-706。
- 回补（2026-10-10，差异登记条目 35）：本期部署实现为 **env 门控简易登录**——`MSF_AUTH_USER`+`MSF_AUTH_PASS` 双 env 同时设置才启用（未设置=本地开发零鉴权，行为完全不变；口令只经部署 env 文件注入，不落库、不进 git）；启用时会话=无状态 HMAC-SHA256 签名 Cookie（`msf_auth=<exp>.<sig>`，HttpOnly+SameSite=Lax，7 天，密钥与主加密密钥同根不同域派生），未认证 /api/** 一律 401 UNAUTHENTICATED（豁免登录/whoami/health 与静态产物）；登录限流=同 IP（反代取 XFF 首跳）错 5 次锁 10 分钟 + 全局 30 次/10 分钟双闸（429 RATE_LIMITED，闭集既有码），口令恒时比较防时序侧信道；CSRF 防线=SameSite=Lax + 未开 CORS + 写操作自带 Idempotency-Key 自定义头（跨站预检不过）。上文 Redis 会话/双提交 Token 为目标架构口径，本条为分期简化实现；鉴权中间件仍按「身份提供者」抽象挂在身份解析之前，OIDC/LDAP 预留不变。

### DSG-N02-2 传输加密
- 规则：浏览器↔app 全链路 HTTPS（含 SSE 通道）；内网部署允许自签或反向代理终止 TLS，但禁止以明文 HTTP 承载会话凭证与业务数据；app↔外部（Git/CI/模型 API）一律 TLS 且校验证书。
- 指标/阈值：TLS ≥1.2（承诺值）；弱套件禁用（建议值，按部署基线扫描结果判定）。
- 验证方式：【测】TLS 扫描（如 testssl）与 HTTP 降级尝试；【审】审查 compose/代理配置，确认无 80 端口直通业务。
- 承接：REQ-803、REQ-710。

### DSG-N02-3 密钥管理（模型/Git 令牌）
- 规则：模型 API key、Git/CI 令牌等机密**只存服务端**，加密落库（AES-256-GCM 或同级），主密钥来自环境变量或 KMS，不进代码库、不进镜像层；主密钥支持轮换——密文带密钥版本标识，轮换窗口内新旧主密钥并存可解密，轮换动作留审计；前端任何 API 响应不得包含机密字段（包括掩码外的残片）；机密不出现在日志、审计正文、证据包、导出文件中。
- 指标/阈值：机密字段在 API 响应中出现次数 = 0（承诺值）；主密钥硬编码扫描命中 = 0。
- 验证方式：【测】遍历设置/模型/Git 相关 API 响应与导出证据包做机密串扫描；仓库与镜像层扫描；【审】审查加解密实现（算法、IV、密钥来源）与日志脱敏过滤器（Bearer/token/key 模式）。
- 承接：REQ-803、REQ-710、REQ-611。

### DSG-N02-4 沙箱执行隔离细则
- 规则：单测/构建/用户命令在**一次性 Docker 容器**执行（HLD ADR-8）：(a) 网络默认关闭——**唯一出向例外为经 `egress-proxy` 的模型调用**：沙箱内嵌 AgentSession 与委派执行体的模型出向一律经 egress-proxy（沙箱出向唯一通道，域名白名单=已配置模型供应商端点，HLD §6/ADR-8）；沙箱内所需模型密钥由平台侧保管，会话级临时注入沙箱环境变量、不写盘、用后销毁（REQ-803）；(b) 依赖卷只读挂载，可写仅限任务工作区卷；(c) 非 root 用户运行；(d) CPU/内存/时长/磁盘限额，超限强杀记失败；(e) 容器即用即毁，任务间不复用；(f) 命令为白名单枚举，不拼接任意 shell（与 DSG-N02-9 互证）。沙箱编排形态以 HLD ADR-8 为准：默认 docker.sock 挂载 + 最小权限补偿（专用 builder 用户、只挂构建所需目录、短命容器），rootless DinD 列为安全加固选项。委派适配器（本机 Claude Code/Codex CLI、远程 Agent 运行时，REQ-610）同样经沙箱或受控运行时，凭证按任务最小注入、用完即撤。
- 指标/阈值：默认限额 2 CPU / 4GB 内存 / 15min / 工作区 2GB（建议值，待压测校准，统稿 D-22）；逃逸与出网尝试检出率 100%（测试集内）。
- 验证方式：【测】沙箱逃逸与负向测试集：尝试出网、写只读挂载、超内存、超长运行、读取宿主路径、fork 炸弹，逐一确认被拦截并记审计；【审】审查容器 run 参数（network/cap-drop/read-only/seccomp/资源限制）与镜像来源。
- 承接：REQ-803、REQ-407、REQ-412、REQ-610、HLD ADR-8。

### DSG-N02-5 上传安全·ZIP 全集（服务端复验）
- 规则：ZIP 上传校验全集与原型 `material-zip.js` 逐条对齐，且在**服务端独立复验**（不信任浏览器结果）：仅 STORE/DEFLATE；逐条 CRC32 校验；文件名必须 UTF-8（无 UTF-8 标志位时仅允许 ASCII）；拒绝加密条目、符号链接、ZIP64、多卷分片、数据描述符损坏、本地头与中央目录不一致；路径拒绝绝对路径、反斜杠、盘符、控制字符、空段/`.`/`..`、末尾点或空格、深度 >24、大小写不敏感重名、文件与目录路径冲突；拒绝数据区重叠；**整包验证通过才一次提交**，任何一条失败整包拒绝，不产生半截数据（REQ-103）。
- 指标/阈值：包 ≤30MB、条目 ≤100、单文件 ≤10MB、总展开 ≤25MB（承诺值，REQ-103）。
- 验证方式：【测】构建恶意 ZIP 样本库（穿越路径、ZIP 炸弹、重叠数据区、伪造 CRC、加密、ZIP64、多卷、深层路径、重名、目录带内容）逐条断言拒绝且库内零残留；【审】逐条对照 `material-zip.js` 的校验项清单审查服务端实现覆盖率。
- 承接：REQ-103、REQ-803。

### DSG-N02-6 上传安全·其他文件类型
- 规则：非 ZIP 上传（doc/pdf/xlsx/md/txt 等）执行扩展名 + 魔数（magic bytes）双重校验的白名单；解析器在隔离 worker/沙箱内运行，解析产出视为不可信文本；HTML/Office 内嵌脚本与外部引用不执行、不加载；单文件大小上限与批量上传总量上限服务端强制。
- 指标/阈值：白名单类型集合 = PRD REQ-102 封闭枚举六种（doc/pdf/xlsx/md/txt/zip；PRD 为唯一来源，本册不复制清单）（承诺值）；单文件 ≤50MB、>50MB 走分片上传（统稿 D-10；建议值，压测后校准）；解析进程崩溃不得影响主服务。
- 验证方式：【测】改扩展名伪装、 polyglot 文件、含恶意宏/脚本/外链的文档样本上传；【审】审查魔数校验表与解析进程隔离边界。
- 承接：REQ-102、REQ-803。

### DSG-N02-7 XSS 防护
- 规则：前端默认经框架转义输出；任何富文本/HTML 注入点（资料解析稿预览、文档正文渲染）必须经 sanitize 白名单（标签+属性两级）；禁止未消毒的 `dangerouslySetInnerHTML`；全局 CSP `default-src 'self'` 起步，按需显式放宽并登记。
- 指标/阈值：注入点 sanitize 覆盖率 100%（承诺值）；CSP 违例上报 = 0 误放（建议值）。
- 验证方式：【测】XSS 向量集对全部用户可控文本入口（文件名、资料内容、文档正文、任务标题、通知文本）逐一注入；【审】代码审查 `dangerouslySetInnerHTML`/`innerHTML` 全部出现点。
- 承接：REQ-803。

### DSG-N02-8 CSRF 防护
- 规则：变更类请求（非 GET）要求自定义头 + SameSite Cookie 双重防线（SameSite 口径以 LLD-5 §1.2 为权威：Lax + 双提交 Token），或显式 CSRF token；GET 请求不得产生任何写副作用（与 BR-04 命令事务互证：写只走命令端点）。
- 指标/阈值：跨站表单提交伪造成功率 = 0（承诺值）。
- 验证方式：【测】跨站伪造表单/图片标签/autosubmit 用例；【审】审查路由表确认无 GET 写操作。
- 承接：REQ-803、BR-04。

### DSG-N02-9 注入防护（SQL/命令/路径）
- 规则：SQL 一律参数化（ORM 参数绑定，禁字符串拼接）；沙箱命令白名单枚举不拼 shell；服务端一切文件路径（对象存储 key、工作区路径）经规范化校验，沿用 ZIP 路径规则（DSG-N02-5）拒绝穿越段。
- 指标/阈值：注入类静态扫描高危 = 0（承诺值）。
- 验证方式：【测】SQL 注入 fuzz、命令注入元字符集、路径穿越向量对全部入口；【审】审查数据访问层与执行器命令构造代码。
- 承接：REQ-803。

### DSG-N02-10 SSRF 防护
- 规则：后端一切出向请求（模型 API、Git、CI、webhook、预览资源拉取）经**出向白名单代理**；禁止按用户输入 URL 任意拉取；拦截内网保留地址段与元数据地址（169.254.169.254 等）；重定向前重新校验目标。
- 指标/阈值：非白名单出向拦截率 100%（承诺值）。
- 验证方式：【测】内网地址段、DNS rebinding、重定向跳转用例；【审】审查出向代理配置与全部 HTTP 客户端调用点。
- 承接：REQ-803、HLD §6。

### DSG-N02-11 预览工件不可信隔离
- 规则：生成的客户工件 HTML、用户上传初稿、构建候选 UI 一律视为不可信内容（README S6/HLD §6）：经 sandboxed iframe 渲染，sandbox 不授予 `allow-same-origin`；工件由**独立子域**承载（与平台主域 Cookie 隔离）；子域响应带严格 CSP（脚本禁用或 nonce 白名单）；iframe 内外通信仅用结构化 postMessage，校验 origin 与消息 schema；工件永远无法读取平台会话与 LocalStorage。
- 指标/阈值：sandbox 属性缺位 = 0（承诺值）；跨域读取会话尝试全部失败。
- 验证方式：【测】工件内植入窃取脚本/父页面操作脚本/弹窗导航脚本，验证全部失效；【审】审查 iframe 属性、子域 Cookie 作用域、postMessage 处理函数的白名单校验。
- 承接：REQ-803、REQ-307、REQ-415、README S6。

### DSG-N02-12 审计不可抵赖
- 规则：全部写操作审计追加：操作者（人工 actorId 或虚拟执行者 runId/token 四元组）、服务端时间、命令、输入指纹、结果；审计表 append-only + 哈希链（HLD ADR-5）；审计写入失败则业务零写、界面不得显示成功（BR-04）；时间一律以服务端为准，客户端时间不作证据。
- 指标/阈值：写操作审计覆盖率 100%（承诺值）；审计缺写容忍次数 = 0。
- 验证方式：【测】命令注册表全枚举回放，逐条核对审计记录；注入审计写入故障验证业务零写；【审】审查命令管线确认审计与业务写入同事务。
- 承接：REQ-706、REQ-803、BR-04、BR-08、BR-13。

## N03 可靠性（DSG-N03）

### DSG-N03-1 命令事务恢复
- 规则：写操作唯一路径为命令管线 prepare（纯计算无副作用）→ publish（单 DB 事务：业务写入+事件追加+审计追加+指纹复核）→ flush（效果入队）；prepare/publish 任何一步失败整体回滚，业务状态、界面、定时器均不变（BR-04）；publish 冲突（版本/指纹/命令 ID 重复）拒绝且不产生部分写入。
- 指标/阈值：任一命令中途注入故障后，残留部分写入 = 0（承诺值）。
- 验证方式：【测】对每个命令类型在 prepare 后、事务中、审计写入点注入故障，断言全回滚；【审】对照 `runtime-hardening.js` 的 prepare/publish 边界审查后端实现。
- 承接：REQ-804、BR-04、REQ-408。

### DSG-N03-2 效果 ledger 幂等补记
- 规则：命令发布后副作用（界面通知、SSE 推送、定时任务、下游失效传播）逐条登记效果 ledger，状态机 pending→running→done/failed/stale；进程重启、页面重进、命令入口执行前调用恢复函数，扫描未完成效果幂等补记；恢复函数可重入，重复执行结果一致（对应原型 `designRecoverPrototypeEffects` 与 `V19_RUNTIME.*Failures` 收据机制）；效果幂等键 = receiptId + 序号。
- 指标/阈值：崩溃点覆盖测试下，补记后效果恰好执行一次的达成率 100%（承诺值）。
- 验证方式：【测】在效果执行前/中/后各注入进程崩溃，重启后断言恰好一次语义与 stale 正确标注；【审】审查 ledger 状态机迁移合法性（不允许 done→其他）。
- 承接：BR-14、REQ-804。

### DSG-N03-3 队列重试与死信
- 规则：队列任务（解析、加工、构建、委派、效果 flush）失败按指数退避自动重试；超过上限入死信队列，产生告警并进入「需你处理」；死信仅可人工重放或人工废弃，动作留痕；重试必须幂等（幂等键去重），不产生重复批次/重复证据（REQ-501）。autopilot runner 步骤链的重试参数以 LLD-2 DSG-F07-1 为权威（指数退避 1s/2s/4s、上限 3 次，统稿 D-11），本条数值为其余队列任务的通用默认。
- 指标/阈值：重试上限 5 次、退避基数 30s（建议值）；死信未处理时长 >24h 触发升级告警（建议值）。
- 验证方式：【测】注入可恢复/不可恢复两类故障，验证重试次数、退避间隔、死信落位与重放；【审】审查任务幂等键设计与重复消费防护。
- 承接：REQ-804、REQ-501、BR-10。

### DSG-N03-4 崩溃一致性
- 规则：服务重启后先执行启动一致性校验（不变式检查：草稿/历史一致性、收据完整性、ledger 悬空项）再开放流量；恢复只做**补记与标注**，绝不重建或谎称修复已丢失历史（BR-05）；异步回调（沙箱完成、委派回传、AI 流结束）提交前重验实时指纹与父运行身份，晚到/失效回调严格零写（BR-08）。
- 指标/阈值：不变式违例检出后服务拒绝开放并告警（承诺值）；晚到回调写入 = 0（承诺值）。
- 验证方式：【测】杀进程点阵测试（命令各阶段 × 回调各时点）+ 重启校验；延迟/乱序回调用例；【审】审查回调入口的四元组（operationId+token+action+owner）重验代码路径无旁路。
- 承接：REQ-804、BR-05、BR-08、BR-14。

### DSG-N03-5 备份策略
- 规则：每日 PostgreSQL 全量 dump + WAL 连续归档；MinIO 桶开启版本化并每日快照；备份产物落独立目录/独立凭证，备份完成做可恢复性校验（非仅文件存在）；备份失败当日告警。对象存储内容寻址保证证据工件可按哈希复原校验。
- 指标/阈值：每日备份（承诺值，REQ-804）；备份保留 30 天（建议值，可配）；备份校验失败 = 0 容忍。
- 验证方式：【测】定时任务触发记录与备份产物哈希校验；模拟备份失败验证告警；【审】审查 compose/脚本中备份范围是否覆盖 PG 全库 + MinIO 全桶。
- 承接：REQ-804、REQ-708、HLD §6。

### DSG-N03-6 恢复演练
- 规则：至少每季度一次、且每次大版本发布前一次恢复演练：从备份还原至干净环境并验证主链路可走通、证据哈希链校验通过；演练过程与耗时留记录。
- 指标/阈值：RPO ≤24h、单节点 RTO ≤4h（建议值，待压测校准，统稿 D-22）；演练记录缺失视同未演练。
- 验证方式：【审】检查演练记录（日期、还原耗时、验证项、签名）；抽查还原环境的证据哈希链校验报告。
- 承接：REQ-804、REQ-708。

### DSG-N03-7 故障注入开关生产禁用
- 规则：测试钩子（原型 `V19_TEST_HOOKS` 对应机制——按 check/page 覆盖自测与 UI 检查结果的故障注入，及 `V19_RUNTIME` 失败收据构造能力）在真实产品中实现为**仅测试环境可用的特性开关**：(a) 生产构建在编译期剔除注入代码路径；(b) 运行时配置双重校验——检测到生产模式且注入开关被请求开启时拒绝启动并告警；(c) 测试环境开启注入时，全部产出证据强制带「模拟」显式标注（BR-11），且不得进入任何真实门禁判定；(d) 开关状态本身记入启动日志与审计。
- 指标/阈值：生产环境注入代码可达路径 = 0（承诺值）；「模拟」标注证据被门禁采信次数 = 0。
- 验证方式：【测】生产构建产物扫描注入符号；生产模式+注入配置启动断言拒绝；测试环境注入结果尝试用于自测/放行门禁断言被拒；【审】对照原型 L8910 `V19_TEST_HOOKS` 的三个注入面（selftestOutcomeByCheck/uiOutcomeByPage/uiOutcomeByCheck）逐一核对真实产品的隔离实现。
- 承接：REQ-804、REQ-505、BR-11、README S5。

## N04 可观测性（DSG-N04）

### DSG-N04-1 结构化日志规范
- 规则：全后端统一 JSON 行日志；必备字段：ts（服务端时间）、level、service/module、operationId、actorId、projectId、commandId（写操作）、traceId；机密、密钥、资料/文档正文、工件内容不写入日志（必要时只记指纹与长度）。

### DSG-N04-2 operationId 全链关联

- 指标/阈值：异步任务 100% 携带父 operationId（承诺值）。
- 验证方式：【测】执行一次完整 autopilot 主线，按 operationId 聚合验证日志/队列/沙箱/审计四视图闭合；【审】审查 ID 生成与透传链路。
- 承接：REQ-805、BR-08、BR-13。

### DSG-N04-3 审计查询
- 规则：审计流水支持按项目、操作者（含虚拟执行者）、命令类型、时间范围、目标对象组合查询；查询接口分页（遵守 DSG-N01-3）；审计导出带哈希链校验信息。
- 指标/阈值：组合查询 P95 <2s（建议值，数据量按 N08-1 的 10 万级审计流水假设，统稿 D-22，待压测校准）。
- 验证方式：【测】大数据量下各组合条件查询计时与结果正确性；【审】核对查询维度与 REQ-706 字段清单一致性。
- 承接：REQ-706、REQ-805。

### DSG-N04-4 指标清单
- 规则：以 Prometheus 格式暴露指标端点（仅内网可达），最小指标集：队列深度/任务时延/重试与死信计数；沙箱执行时长分布/失败率/超限强杀计数；模型调用次数/token 用量/估算成本/错误率（按模型与用途分维度，REQ-612）；API 时延与错误率；SSE 在线连接数；DB 慢查询计数与连接池水位；PG/MinIO 存储用量；命令成功率（按命令类型）。
- 指标/阈值：上列指标覆盖率 100%（承诺值）；指标端点不含机密与正文内容。
- 验证方式：【测】抓取指标端点逐项核对存在性与标签维度；【审】对照清单审查埋点位置。
- 承接：REQ-805、REQ-612。

### DSG-N04-5 告警阈值
- 规则：告警规则配置化，最小告警集：死信 >0；队列深度 >100 持续 5min；备份失败或备份校验失败；磁盘/对象存储用量 >80%；沙箱失败率 1h 内 >30%；模型调用错误率 1h 内 >20%；审计写入失败（任意一次即告警，最高级）；故障注入开关异常（N03-7）。
- 指标/阈值：上列为建议默认值，可配置；审计写入失败告警延迟 <1min（承诺值）。
- 验证方式：【测】逐一注入各告警条件验证触发与恢复通知；【审】审查告警规则配置与通道联通性。
- 承接：REQ-805、REQ-804。

## N06 可维护性（DSG-N06）

### DSG-N06-1 模块边界检查
- 规则：模块依赖方向静态检查纳入 CI：领域服务之间不直接共享表、不跨模块 import 内部实现，跨域引用一律经对端工件身份（ID+指纹，HLD §3）；横切服务（命令事务/审计/放行策略）单向被依赖；违规 import 使构建失败。
- 指标/阈值：边界违规 = 0（承诺值）。
- 验证方式：【测】CI 跑依赖边界规则（如 dependency-cruiser/eslint import 约束）；故意引入违规 import 验证拦截；【审】审查规则配置文件与模块清单同步。
- 承接：REQ-807、HLD ADR-1、BR-03。

### DSG-N06-2 测试覆盖率目标
- 规则：覆盖率按模块设定批准目标并逐模块登记；默认起步目标：行覆盖 ≥80%、分支覆盖 ≥70%；核心正确性模块——命令事务、指纹与失效传播、UI 评分与通过语义、门禁/放行策略、审计——目标上调为行 ≥90%、分支 ≥80%；覆盖率不达标 CI 拦截；BR-01~BR-15 每条至少一个自动化负向测试（PRD §7.2）。
- 指标/阈值：默认行 ≥80% / 分支 ≥70%；核心模块行 ≥90% / 分支 ≥80%（承诺值，起步目标，逐模块批准后可修订）。
- 验证方式：【测】CI 覆盖率门禁与按模块报告；【审】核对模块目标登记表与 BR 负向测试清单（负向矩阵：过期证据不能放行、跳过不算通过、晚到回调零写、审计失败零写、历史版本不可变）。
- 承接：REQ-807、BR-09、PRD §7.2。

### DSG-N06-3 代码规范与命令注册纪律
- 规则：全仓 TypeScript strict；ESLint + Prettier CI 强制；新增写操作必须同步完成四件套：封闭命令枚举注册、审计映射、效果定义、自动化测试（缺任一 CI 拦截）；禁止以原型式直接突变状态的方式写业务状态。**错误码闭集纪律**：一级错误码（DomainError）唯一注册表为 LLD-3 §14，二级门禁/缺口子码（issue code）唯一注册表为 LLD-3 §15（边界定义见 LLD-3 DSG-C14-1）；新增/修改码值必须先注册后使用，废止码保留不删（DSG-C14-3）。
- 指标/阈值：lint/format/类型检查违规 = 0（承诺值）；未注册写路径 = 0；错误码闭集校验违规 = 0（承诺值）。
- 验证方式：【测】CI 静态检查与命令注册表完整性校验脚本；**错误码闭集校验：CI 运行 `node doc/product-design/tools/check-codes.mjs`，零违规（退出码 0）方可通过**；【审】抽查近期新增命令的四件套齐备性；抽查新增码值已先注册于 LLD-3 §14/§15。
- 承接：REQ-807、BR-04。

## N07 数据保留与隐私（DSG-N07）

### DSG-N07-1 证据默认永久保留
- 规则：证据、报告、批次、交付决定、文档历史版本、审计流水**默认永久保留**；append-only 存储不提供常规删除/修改接口（DB 角色禁 UPDATE/DELETE，HLD ADR-5）；项目不可删除只可归档，归档不删任何证据（统稿 D-17，REQ-808 优先），管理操作不得级联清除证据。
- 指标/阈值：证据类数据删除接口存在数 = 0（承诺值）。
- 验证方式：【测】以应用身份对证据表执行 UPDATE/DELETE 断言被 DB 层拒绝；【审】审查 DB 角色权限与 API 面。
- 承接：REQ-808、BR-03。

### DSG-N07-2 可配置保留策略
- 规则：非证据类数据（运行日志、通知、会话、临时中间工件、死信已处理记录）保留期可配置；保留策略的每次变更本身留审计；到期清理由受控任务执行并留清理清单；任何保留策略不得作用于 N07-1 列举的证据类。
- 指标/阈值：默认保留期——日志 90 天、通知 180 天（建议值）；策略误删证据事件 = 0。
- 验证方式：【测】构造到期数据验证清理范围精确（白名单表级）；【审】审查清理任务的表清单与证据表黑名单硬约束。
- 承接：REQ-808、REQ-706。

### DSG-N07-3 脱敏加工适用规则
- 规则：内置脱敏（人名/邮箱/电话等模式，REQ-111）只作用于**解析稿树的派生副本**，原件树永久保留且不脱敏（REQ-102/105）；脱敏为不可逆加工，作业执行前明示；脱敏规则集版本化管理，每批加工记录所用规则版本；脱敏产物用作 AI 参考输入时仍需过 REQ-114 定稿门禁。
- 指标/阈值：原件被脱敏加工修改次数 = 0（承诺值）；加工记录规则版本缺失 = 0。
- 验证方式：【测】脱敏作业后原件哈希不变、副本命中模式被遮蔽、漏检模式按样本集统计；【审】审查作业实现确认只写解析稿树。
- 承接：REQ-111、REQ-102、REQ-105、REQ-808。

### DSG-N07-4 数据不出内网与模型出向
- 规则：平台数据（资料、文档、证据）默认不出内网（REQ-710）；唯一的出向通道是白名单内的模型 API/Git/CI——凡经模型 API 发送的内容（参考上下文、评审材料）对用户可见可审计（提示词版本+输入指纹，HLD ADR-6）；使用外网模型时，资料引用装配范围需在项目设置中显式确认；支持配置本地推理模型以满足零出网。
- 指标/阈值：非白名单出向 = 0（承诺值）；模型调用上下文可溯率 100%。
- 验证方式：【测】出向流量抓包核对白名单；抽查 AI 生成记录的输入指纹可回放装配内容；【审】审查编排层上下文装配与出向代理配置。
- 承接：REQ-710、REQ-608、REQ-614、REQ-803。

## N08 容量规划（DSG-N08）

### DSG-N08-1 单节点规模假设
- 规则：本期容量设计基线：单节点支撑 20 并发用户；单项目 100+ 开发任务、1000+ 资料文件、50+ 文档版本历史下各项性能承诺（N01）不降级；容量基线数据造数脚本纳入仓库，性能回归基于该基线。
- 指标/阈值：20 并发 / 100+ 任务 / 1000+ 文件（承诺值，REQ-802）；参考部署规格 4C/8GB/SSD 500GB（建议值，待压测校准，统稿 D-22）；AI 规模假设：单项目 ≤5000 会话消息、≤10 万证据记录（建议值，统稿 D-22）。
- 验证方式：【测】基线造数 + 并发压测脚本验证 N01 全部承诺值；【审】审查造数脚本与 REQ-802 的一致性。
- 承接：REQ-802、REQ-801。

### DSG-N08-2 存储容量估算与水位
- 规则：按「资料原件+解析稿、工件与构建产物、证据截图、报告导出、审计与日志」分类估算增长；MinIO 与 PG 用量纳入指标（N04-4）并设水位告警；内容寻址天然去重，重复上传同内容不重复占空间。
- 指标/阈值：单项目年增长估算模型登记在运维手册（建议值）；存储 >80% 告警（承诺值，与 N04-5 一致）。
- 验证方式：【测】基线数据量下实测存储占用，校准估算模型；【审】审查容量监控面板与告警规则。
- 承接：REQ-802、REQ-708、REQ-805。

### DSG-N08-3 扩容路径
- 规则：预留扩容路径且不要求改写业务接口：队列 worker 可独立横向扩容（多实例消费同一队列）；MinIO 可切换分布式部署；PostgreSQL 可加只读副本分担审计查询；app 无状态化（会话在 Redis）为多实例预留——但本期仅交付单节点 Compose，不为扩展做超额实现（HLD §8）。
- 指标/阈值：worker 扩容验证通过（建议值）；本期不承诺多节点 SLA。
- 验证方式：【测】增加 worker 实例验证吞吐近线性提升与幂等无冲突；【审】审查 app 无状态假设（无本地盘会话依赖）。
- 承接：REQ-802、REQ-710、HLD ADR-1。
