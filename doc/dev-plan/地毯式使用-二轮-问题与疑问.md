| W2-001 | 🟠 严重 | TC-R-01/TC-A-02 | AI 生成（CRD 整篇）与对话栏提问失败时**前端静默**：生成 modal 直接关闭、文档停留「待生成」、无任何错误提示；对话栏只显示「生成失败」四字，无原因、无重试指引。本次实因是网关 401（key 失效），用户视角完全无从知晓 | 预期：stream.error 应呈现错误码+人话原因+下一步指引（如「模型调用失败（401），请到设置页检查模型密钥」）；实际：零反馈 | SSE 直读 `stream.error code=MODEL_UNAVAILABLE`；审计 genState=failed ×2；直调网关实证 401 Invalid API key |
| W2-002 | 🟡 一般 | TC-A-11/TC-N-05 | AI 调用失败可观测性缺口：SSE error 帧只带 code 不带 message（「401 Invalid API key」被 MODEL_UNAVAILABLE 吞掉）；ai_messages 失败行无错误字段；后端 stdout 无 AI 调用失败日志（U-009 同类缺口存在于生成/chat 链路，一轮只修了资料解析链路） | 预期：失败原因（脱敏后）落 message 行/日志/错误帧；实际：三层皆无 | 直调脚本才拿到真实 message；ai_messages status=failed content 空 |
| W2-003 | 🟡 一般 | TC-M-11/12 | 批量解析完成后资料树不自动刷新：两文件 DB 已 parsed，UI 仍显示「解析中…/待解析」，手动刷新页面才变「已解析」 | 预期：作业完成后树状态自动更新；实际：滞留旧态 | DB parse_status=parsed vs UI 快照对照（2026-09-29 22:2x） |
| W2-004 | ❓ 疑问 | TC-G-08 | 设置页模型 conn_status 显示 ok（updated 14:14），但该 key 实际已 401 失效——conn_status 是「上次成功时戳」还是实时探测？若是缓存态，标签误导 | 预期：连接状态反映最近一次真实调用结果，或明示「上次验证时间」；实际：key 已失效仍显 ok | ai_models.conn_status=ok vs 网关 401 |
| W2-005 | 🟠 严重 | TC-X-01 | 幂等键语义未实现：LLD-5 DSG-A01-3 承诺「同 (actor,method,path,key) 重放返回首个响应不重复执行；同键异载荷 409 IDEMPOTENCY_CONFLICT」，实机同 key 异体 POST tools:invoke 返回 200 正常执行——中间件只校验头存在性（注释自认「收据缓存随 Redis 接线补全」，Redis 早已接线但缺口遗留至今）。命令层 revision/指纹校验兜住了多数场景，但无收据缓存的端点重复提交会重复执行 | 预期：A01-3 全口径（收据缓存+异体冲突 409）；实际：仅存在性校验 | 实机同 key 异体重放 200；idempotency.middleware.ts L5 注释 |
| W2-006 | 🟠 严重 | TC-R-14 | PRD 整篇生成产出内容为 AI 索要参考资料（「请提供参考资料……我无法逐条核对」）——CRD 已定稿 v2 且资料双定稿，但 PRD 生成 prompt 未让模型看到任何上游内容。章节进度条却显示各 CR 条目「生成 ✅」，进度与真实产出脱节 | 预期：PRD 生成应以 CRD 定稿稿为输入（LLD 口径），模型可见上游全文；实际：模型声称无资料，产出索要文本。疑 prompt 只注入本文档（prd）的 req_doc_refs，CRD 定稿内容未注入 | 补丁原文快照；CRD 已定稿 v2；一轮同路径曾正常（地毯项目 PRD 60+ REQ） |

| W2-008 | 🟠 严重 | TC-R-15 | 增量修订完成后前端补丁区不刷新：生成结束（补丁已落库 14 条 pending）页面无任何补丁条、无「补丁 ×N」徽标，手动刷新页面后 14 条全部出现 | 预期：stream.done 后 patches 自动重拉渲染；实际：需手动刷新 | API patches 14 pending vs 页面 0 条；reload 后 14 条渲染 |
