# 设计覆盖检测·原型对应·综合可交互原型 — 设计

> 2026-10-15 立项。缘起（用户原话）：「概要设计文档与详细设计文档如何检测能完全覆盖需求 PRD，
> 并不过度设计；如何保障将最新的设计文档与 UI 原型的单页面都能对应上，并最终出综合的可交互 UI 原型」。
>
> 勘查钉死的现状缺口：①RTM 只查 from 侧正向三层（R→CR/CR→REQ/REQ→DSG），**无反向「过度设计」检出**；
> coverage-fix 只补 CRD/PRD 两域不覆盖 L0C_BELOW；②原型页表只记 catalog_version+指纹，**无「依据哪些
> 册/章节」结构化记录**，页级 prompt 不注入 UI 册正文；③汇总原型跨页交互止于跳页/切态，
> **flow 条目不渲染不校验**；DR 评审是三条 mock 种子+人工结论（review.service.ts 注释自标
> 「M6 真接后由自检评审产出」）。
>
> 用户拍板三决策：①过度设计=**规则筛查+AI 复核**；②对应=**结构化对应+双向检查**；
> ③原型交互=**全套（页内穿流+流程视图+flow 校验）**。

## 1. PRD↔设计 覆盖与过度设计检测

**覆盖侧补强**：「AI 补齐缺口定向提案」扩展到 **L0C_BELOW**（REQ→DSG 缺口）——**落域钉死**：
在 design/generate.service.ts 新增 coverageFix 段（复用 design.doc.propose-pending 落 dsg_pendings；
**req 域不直写 design 表**——跨域只读纪律）；**选册规则**：逐缺口 REQ 向 **hld** 提案一条承接章节
（hld 是需求→设计第一落点；提案本就人工确认，确认前可改）+ 锚点回引 REQ-nnn 满足 L0c 派生。

**过度设计侧（规则+AI 两段）**：
- 规则筛查：rtm-health 增反向维度——**筛查对象=设计册内含本册锚点码（prefix-N）的条目节**
  （无码的大章/总则/约定节不查），节标题与正文均无 REQ-nnn 回引即入「疑似过度设计」候选清单；
  **册级粗链不算承接**（逐节判定，册内存在粗链不豁免其它节）；
- 人工豁免：rtm_links 自指行 deferred 同款（理由必填、不计待办）——`rtm.deferred.mark/unmark` 的
  nodeKind 枚举扩 `'dsg'`（纯 TS 类型扩展，from_kind 无 CHECK 零迁移；DSG 码与 R/CR/REQ 编码不撞，
  不污染 L0a/b/c 分母）；UI 入口=候选清单一键标豁免；
- AI 复核：`purpose='review'`（PURPOSES 闭集现成），命令 `design.review.selfcheck` 注册，
  触发=设计页「✦ 自检评审」钮（长调用常驻进度 db16b31 先例，逐节串行+进度条+可后台）；
  候选清单逐节产复核意见（「看似无需求依据：…/实为合理技术决策：…」）；
- 复核意见落成**真实 DR 评审项**（dsg_reviews 现 schema 可承载**不加列**：text 装意见、
  created_by='pi' 辨识来源、人工三值结论走既有 design.review.conclude）：
  code 生成规则=`DR-<册字母>-<节锚点>`（如 DR-H-h-3）→ reseed 幂等先例（WHERE NOT EXISTS）天然去重；
  **重跑口径**：同 code 已有结论（done）不动、仍 open 的刷新 text 与复核时间；
  **快照式接受陈旧**（无 anchor/fingerprint 列——章节漂移后意见可能陈旧，人工结论时自行判断，
  重跑自检即刷新）；三条 mock 种子（DR-01~03）保留不动（真实项量产後自然稀释，不做退役动作）；
  **量级提示**：finalize 门禁是全项目 open DR 计数——自检量产后所有设计册定稿都会要求逐条人工结论
  （或 allowOpenReviews 二次确认），这是「AI 只提不判」的意图内行为。

## 2. 设计文档↔原型单页 结构化对应 + 双向检查

- `dsg_catalog_refs` 增 `ref_kind='ui'`：**需迁移 0031**（0006 建表 CHECK 只含
  ('hld','lld','prd','src','task')——ALTER 重建 CHECK 含 'ui'；全 spec 唯一 schema 变更，
  dsg_reviews 不加列、manifest 是 dsg_versions.content jsonb 内扩展、deferred 零迁移）；
  plan 时页面条目同步写「页→ui 册章节」refs（快照+ref_fingerprint，挂点=pageSeeds 来自
  uiSecs 分支的天然位置）；refs 写入后 plan 才有——**refs 未声明≠缺失**（见兼容口径）；
- 页级 prompt 注入 UI 册正文（页面相关章节优先，节选上限同 PRD 24000 口径）；
- 双向一致性检查（进 check 与状态查询）：册有页无（UI 册页面章节无目录页）/页有册无
  （目录页无 UI 册章节承接）/内容滞后；
- **滞后判定改时间基（评审 C1 修法，零新增快照）**：页 `updated_at` < 其依据 ui 册当前版本
  `submitted_at` → 滞后（「该页依据的 ui 册 §x.y 已变更」）——页重生成 updated_at 刷新即自动解脏，
  与 upstream-stale.ts 先例同构；滞后页进 PROTOTYPE_DIRTY 同款门禁（pageDriftIssues 并列）；
- **§2 豁免落点**：目录条目 payload 增 `exempt: true`（页有册无的人工豁免，随 catalog_version
  自包含；与 §1 的 rtm deferred 是两套对象两个机制，UI 文案各自说明）；
  **exempt 设置通道=design.catalog.update-item 字段清单含 exempt**（或独立 toggle 同命令）；
  **派生条目的 steps/exempt 修改在 re-plan 全量重导时按 type+code 随行迁移**（W7-002 现只随行
  source='manual' 条目——本特性扩为派生条目的人工修改字段也随行，防 re-plan 丢人工调整）；
- **新旧目录判别式**：该目录版本存在任一 ref_kind='ui' 行即按新口径检（此时仅有 prd refs 而无
  ui ref 的页才算「页有册无」）；全版无 ui refs 视为旧口径不检；**ui 册后于 plan 定稿的，
  需 re-plan 才建立 refs**；
- 可追溯呈现：原型页签显示「本页依据：ui 册 §x.y（✓一致/⚠已变更）+ PRD REQ-nnn」。

## 3. 综合可交互原型（穿流+流程视图+flow 校验）

- **页内点击穿流**：页面契约增 `data-nav` 属性（页级 prompt 约定：跳转类按钮/链接挂
  `data-nav="#P-002"` 可带状态 `#P-002/s2`；纯展示按钮不挂）；validatePageHtml 增校验
  （目标必须是目录内页码——校验需要目录页码集，start() 已查全量 items 须传入）；
  汇总 NAV_SCRIPT 增事件委托——点击 [data-nav] 切目标页+hash 同步；
  **目标块不存在时 no-op**（单页预览直开场景防白屏）；
- **流程视图**：flow 条目（F-001 步骤链）进汇总渲染——汇总增「流程」视图：每 flow 一条步骤条
  （步骤=页面/状态引用），点击步骤跳对应页面状态；
- **flow 步骤声明与编辑**：plan 时 seed（从 UI 册流程章节/PRD 推导）+ **新增命令
  `design.catalog.update-item`**（限定可改字段=title/note/payload.steps；改即新 catalog_version，
  与 PLAN_STALE 联动同 add/remove 口径）+ PrototypePanel 流程步骤编辑 UI（现有 add/remove 按钮旁）；
- **flow 校验进 check**：flow 引用的页面/状态必须存在+data-nav 目标必须存在——**进 check 报告
  issue，不过则拦定稿**（CHECK_REQUIRED 路径；issue 码只进 dsg_prototype_checks.issues jsonb，
  PAGE_MISSING/STATE_MISSING 先例，不入 DomainError/GateIssue 闭集）；
- **兼容口径（评审 I3 钉死）**：旧目录版本无 ui refs→双向检查对 refs 未声明的页**不检页有册无
  方向**（缺省≠缺失）；旧格式 flow steps（payload.steps 为 REQ 章节标题字符串）按「未声明引用」
  不校验；新校验（ui refs/data-nav/flow 引用）**只对新 plan 之后的目录版本生效**；
- **冻结兼容**：manifest 增 flow 快照+data-nav 目标清单（jsonb 内扩展零迁移）；
  旧版汇总原型（无 data-nav）永久可预览，新校验只对新生成生效。

## 纪律与测试口径

- 错误码闭集零新增；审计失败零写；豁免/DR 结论/定稿全部人工（AI 只提不判——铁纪律）；
- 跨域只 SQL 直读不写；console 只 warn/error；样式全 var()；toast kind 只 default|success|warn；
- 嵌套 LLM 绝不在命令事务内（AI 复核/页级生成全在事务外）；
- 单元：反向筛查纯函数（无回引检出/豁免剔除/粗链不算承接）；data-nav 校验；双向一致性检出；
- 集成（101 跑）：L0C coverage-fix 定向提案落设计册；AI 复核→DR 项落库→人工结论挂门禁；
  plan 写 ui refs→ui 册新提交（时间基）→受影响页面清单→重生成解脏；flow 校验拦截；穿流契约 validatePageHtml；
- 回归：既有 **344 基线**全绿（2026-10-14 实测——条目 44 后口径）；旧版汇总原型预览兼容；
- 差异登记追加条目 45，待 13 册下轮基线回补（LLD-5 RTM/原型链、LLD-2 dsg_catalog_refs、LLD-6 原型页签）。
