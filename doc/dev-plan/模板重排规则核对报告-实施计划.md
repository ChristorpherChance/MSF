- [ ] **Step 1: 写失败测试（先红）**——断言矩阵：
  1. 完全对版（大章集合/顺序/章名全同+锚点顺连续+编号规范）→ issues=[];
  2. 缺章：「缺失：模板第 4 章『四、xxx』」类行；多章：「多余：『七、附录』模板无此章」类行；

  4. 共有章相对顺序颠倒 → 「顺序错位」行；
  5. 无缺失无多余但同位章名不同 → 「章名不符」行；
  6. 锚点重复必报；有条目节（`## ` 级标题非大章形态）但零锚点 → 「条目节缺锚点码」一行；
  7. 编号断号/跳号各产一行；
  8. `chapterTitlesOf` 为空但存在 `## ` 级标题 → 只报「大章编号不规范」一行，且**第 1 维零行**（不双报）。

- [ ] **Step 2: 实现**

```ts
/** auditSkeleton 报告（设计 §1）：issues 空=对版；人话行直接进弹窗明细 */
export interface SkeletonAudit { issues: string[] }

/**
 * 四维之结构三维（纯函数）：大章对照三段式 + 锚点码完整性 + 编号规范。
 * anchorPrefix：CRD='CR'/PRD='REQ'/设计册=chapter_prefix 单字母（h/o/g/k/d/a/u/n），
 * 条目节标题形态 `## {prefix}-{数字} 标题`（需求域三位数 CR-001/REQ-001，设计册 h-1）。
 * 判据权威：doc-conventions.ts reqSectionRule/designSectionRule 与 CHAPTER_RULE。
 */
export function auditSkeleton(content: string, templateChapters: string[], anchorPrefix: string): SkeletonAudit
```

实现要点（规格钉死，勿自由发挥）：
- **优先级闸**：`chapterTitlesOf(content)` 为空且 `/^##\s+/m` 有命中 → issues=['大章编号不规范（大章须用中文数字序号+顿号，如 一、xxx）']，**直接返回不做第 1 维**（锚点/条目节维度仍跑——它们与章形态无关）；
- **大章三段式**：①集合差（模板有文档无→缺失行；文档有模板无→多余行）；②章名交集的相对顺序比较（actual 中交集序列 vs expected 中交集序列不同→顺序错位行，行内点出首对错位章）；③仅当①无缺失无多余时逐位比章名→不符行；
- **锚点维度**：正则 `^## (${prefix}-\d+)\s` gm 全量提取；重复码（出现 >1 次）每码一行；零锚点且存在非大章 `## ` 级标题（疑似条目节）→「条目节缺锚点码」一行；
- **编号维度**：提取到的锚点数字序列检查顺连续（1 起；需求域允许 CR-001 起）——断号（缺中间号）/跳号（>1 步进）各产一行；重复在第 2 维已报**不重复报**；
- issues 行序=维度序（大章→锚点→编号），行内人话带章名/码。
