## 1. 目标与边界

**目标**：把 `doc/msf-prototype.html` 原型（行为基准，快照存于 `doc/product-design/prototype/`）按产品文档体系实现为自托管 Web 应用——React 18+TS+Vite+Zustand 前端 / NestJS 后端 / PostgreSQL 16 / MinIO / Redis+BullMQ / Docker 沙箱 / Pi SDK AI 编排（HLD §2）。

**本期不做**（PRD §1.3 / HLD §8 冻结边界）：生产发布实现（仅预留接口 REQ-712）、多用户 RBAC（仅数据模型预留 REQ-707）、多租户、移动端原生、K8s。

**用户已拍板的开发决策（2026-09-21）**：
1. 仓库形态：pnpm monorepo（`apps/web`、`apps/server`、`packages/shared`），仓顶 git 管理。
2. 推进方式：**逐域完整推进**——资料域完整做完再做需求域，依次类推；横切基座（M02/M11/M12 核）在 M0 先行，理由见 §3。
3. AI 链路：M08 接口按 Pi SDK 0.86.0 实物事实建模，**mock 实现先行**，真接 Pi 在 M6。

## 3. 关键依赖与排序理由

1. **M11（证据与审计）/M12（策略引擎）/M02（API 层）核必须在 M0 先行**：LLD-1 DSG-M00-1 调用矩阵——M11 被全部写路径调用（审计失败零写），M12 单向被各域确认点调用，M02 是领域服务唯一对外暴露面。若后置，每个域的命令事务都要返工。
2. **域顺序跟随业务主链**（HLD §5）：资料（M03）→ 需求（M04）→ 设计（M05）→ 开发（M06）→ 测试验收（M07）。下游域的输入恰是上游域的定稿产物，逐域完整推进时集成风险最小。
3. **AI mock 边界**：M0 在 `apps/server/modules/ai/` 定义 Provider/Session/Usage 接口（按 Pi 0.86.0 事实：Usage 附着消息结果、steering=注入消息、stop=abort、pause/resume=平台缓冲层），mock 实现使 M2（需求文档生成）起链路可跑；M6 以 Pi SDK 真实现替换，接口不返工。
4. **M09 沙箱与 M10 集成在 M6**：M4（开发域）的自测/构建先以本机临时执行器占位（明确标注为过渡实现，不带出向网络），M6 统一迁入沙箱。

## 4. 里程碑定义

### M0 工程基座

- **入口条件**：开发计划批准（本文件）；Node ≥22.19 环境（见 §6 环境清单）
- **内容**：monorepo 仓架与 CI 五道闸；compose 六服务骨架；packages/shared（错误码注册表从 LLD-3 §14/§15 生成、状态机枚举、JCS+NFC 指纹工具）；M11 命令事务核（CommandBus 封闭命令枚举、审计 append-only + UNIQUE(prev_hash) 双链、效果 ledger 骨架）；M12 核（7 确认点策略表、默认人工求值器）；M02 骨架（DomainError→HTTP 映射、幂等键、本地默认身份）；M13 最小集（projects 表+CRUD）；web 骨架（设计令牌、五阶段路由占位）
- **出口门禁**：`pnpm typecheck/lint/test` 全绿；dependency-cruiser 边界规则生效（违规 import 使构建失败）；`check-codes.mjs` 零违规；compose 三基础服务起后 `/health` 三连通；命令事务冒烟（审计链式追加 + 旁路写被拦截）；核心模块覆盖率 ≥90%/80%（N06-2）
- **承接**：BR-01（命令事务）、BR-03（证据不可变）、BR-04（写操作命令化）、BR-06（人工确认点）的基板部分、REQ-701（项目管理最小集）

### M1 资料域（M03，REQ-101~115）

- **入口条件**：M0 出口门禁全过
- **内容**：`mat_files`/`mat_parsed`/`mat_folder_tree`/`mat_batch_jobs`/`mat_batch_items`/`mat_uploads` 六表（LLD-4 D03-1~7，含分片行锁串行化）；上传会话/分片/完成/中止（A03-1/2/3/18，天然键幂等豁免）；ZIP 安全校验链全拒绝条件（LLD-2 F09-1）；解析状态机（F02-3）；批量加工作业五态（F02-4，弹窗快照/开始复核/变化行跳过）；文件与内容定稿（A03-11/12）；参考输入门禁（A03-17）；资料页 UI（LLD-6 §3.2 三栏工作模式、批量弹窗）
- **出口门禁**：REQ-101~115 逐条验收用例通过；ZIP 攻击样本负向测试全集通过（F09-1 拒绝条件逐条）；批量作业中断/恢复/停止行为与原型一致；A03-1~18 端点全实现且错误码闭集

### M2 需求域（M04，REQ-201~210）

- **入口条件**：M1 出口门禁全过（资料定稿产物可作为需求参考输入）
- **内容**：`req_documents`/`req_versions`/`req_drafts`/`req_pendings`/`rtm_links`/`rtm_health`/`req_doc_refs` 表（D04-1~7）；文档生命周期状态机（F02-1：clean/dirty/finalized + pending-review 正交标记，undo ≤30，发布前不变式 INV-DOC-1~6）；待确认补丁（propose/accept/reject，AI_BASIS_INVALID/PATCH_BASE_STALE 门禁）；RTM 与健康度（F06 四指标实算、空分母条款、L0C_BELOW 缺口子码）；需求页 UI（§3.3，工具栏三态同构）

### M3 设计域（M05，REQ-301~312）

- **入口条件**：M2 出口门禁全过；L0a≥0.95 且 L0b=1（产品内门禁，开发自验证用）

### M4 开发域（M06，REQ-401~420）

- **入口条件**：M3 出口门禁全过
- **内容**：`dev_tasks`/`dev_operations` 等表（D06-x）；任务池/计划/看板四列+blocked（F02-5，含 task.rework 评审驳回回路）；异步操作四元组身份（F01-2）；autopilot 授权/暂停/接管/停止；自测四门（F02-7，功能检查/联调与冒烟/UI 符合度/开发审核）；转测试交接；开发页 UI（§3.5）
- **出口门禁**：REQ-401~420 逐条验收；四元组身份零写负向用例（opToken 不匹配/快照失效严格零写）；自测四门与原型行为对齐（显示名+键名）

### M5 测试验收域（M07，REQ-501~511）

- **入口条件**：M4 出口门禁全过
- **内容**：`tst_*` 表（D07-x）；批次状态机（F02-8，含 block/unblock 与 A07-13/14）；用例执行与 not-run 保留分母（BR-09）；缺陷五态闭环（PRD REQ-506 权威）；报告与条件放行（REQ-509 已裁决放宽边界）；交付决定工件；测试页 UI（§3.6）
- **出口门禁**：REQ-501~511 逐条验收；条件放行豁免逐项写入交付决定工件且留痕；BR-09 负向用例（skip/not-run 不美化）

### M6 AI/执行/集成（M08 真接 + M09 + M10）

- **入口条件**：M5 出口门禁全过；模型供应商密钥就位（设置页）
- **内容**：Pi SDK 0.86.0 真接（pi-ai 模型/计量、pi-agent-core 运行时、pi-coding-agent 会话；委派 pi RPC 首选）替换 mock，接口不变；Usage 从消息结果提取落库、price_table 兜底（ADR-6）；沙箱执行器（docker.sock+最小权限补偿，ADR-8；出向唯一通道 egress-proxy）；Git 平台适配与 CI webhook（A06-21/22、sys_webhook_secrets）；委派（A08-x）
- **出口门禁**：真实模型完成一次 PRD 生成端到端；沙箱内任务出向仅经 egress-proxy 白名单（负向：非白名单域名不可达）；CI webhook HMAC 校验与幂等（delivery_id）
- **注意**：pi-web-ui 助手 dock 聊天组件浅 fork 在本里程碑做（0.75.3 滞后主线，裁剪依赖，维护责任归平台，HLD §2/ADR-6）

### M7 端到端验收

- **入口条件**：M6 出口门禁全过
- **内容**：全局助手/通知/任务中心/设置/备份（M13 补齐，REQ-701~712）；性能达标核查（LLD-7 N01，含 REQ-801 首 token 分档目标值）；安全核查（N02 清单逐项）；备份恢复演练（N03）；**对照原型行为验收矩阵**（原型回归测试集 30 套的产品版对应）全量通过；C-6/C-11 压测校准并回销
- **出口门禁**：BR-01~15 逐条签收；P0 85 条 REQ 全部「已验收」；LLD-7 承诺值全达标

## 5. 工程纪律落地映射（LLD-7 N06 → 本仓机制）

| 纪律 | 机制 | 位置 |
| --- | --- | --- |
| 错误码闭集、先注册后使用 | `packages/shared` 的错误码 TS 常量由脚本从 LLD-3 §14/§15 表格生成；代码引用表外码即类型错误；CI 跑 `check-codes.mjs` | `packages/shared/scripts/gen-error-codes.mjs` |

| 覆盖率门槛 | vitest coverage：默认行 80%/分支 70%；evidence/policy/命令事务相关包 90%/80% | 各包 `vitest.config.ts` |
| 文档变更纪律 | product-design 13 册冻结基线；开发中发现设计问题 → 先走 README §5 修订文档（同步 RTM+基线重登），再改代码 | 流程约定 |
