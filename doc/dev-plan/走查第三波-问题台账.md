### #15 L0c 口径悬空：PRD 必须预埋 DSG-* 锚点，但生成链路从不产、设计文档也没有、报错零引导（阻断性）
- **阶段**：设计→开发（dev/tasks:identify 门禁）
- **现象**：八册全部定稿、原型定稿后，开发识别 423 GATE_BLOCKED：全部 18 条 REQ「REQ→DSG 无承接锚点」，L0c=0。
- **根因**：rtm-health.ts deriveLinks 只从 **PRD 正文**派生 REQ→DSG implements（REQ 章节标题 + 正文内 `DSG-*` 锚点）。但①PRD 生成 prompt 从不产 DSG 锚点；②设计八册正文也不带任何 DSG-* 锚点（实测 0 个），锚点无处可指；③门禁报错只列 REQ 编号，用户无从知道要去 PRD 补 DSG 锚点。而设计文档里实际写了大量 REQ-nnn 回引（HLD 18 条全），这个"自然的"承接方向完全不被派生识别。
- **定性**：产品口径与生成链路脱节 + 引导缺失。要么派生增加"设计文档 REQ 回引"方向，要么生成 prompt 要求 PRD 产 DSG 锚点并在报错中给出修复指引。
- **处置**：本次走查用增量修订在 PRD 各 REQ 章节补「设计承接：DSG-*」锚点解锁流程；口径问题记录待立项（与 #10/#11 同类：生成质量/追溯链）。

### #16 dev plan:submit/approve 缺入参校验，空 body 裸 TypeError 落 500（已修）
- **阶段**：开发（dev/plan:submit）
- **现象**：`POST /dev/plan:submit {}` → 500 INTERNAL「内部错误」，后端日志 TypeError: Cannot read properties of undefined (reading 'length')（plans.service.ts:26）。
- **根因**：submit 命令直接读 `taskIds.length`、approve 直接 `revision.replace`，缺 body 校验。
- **处置**：submit/approve 加入参兜底，缺参抛 VALIDATION_FAILED(400)。同类「body 缺字段→500」风险在其它命令也可能存在，待专项排查（举一反三项）。

### #17 dev 任务冒号动作路由全部被吞：:transition/:run/:progress/:quality/:ai-review 落 500（阻断性，已修）
- **阶段**：开发（看板操作）
- **现象**：`POST /dev/tasks/<id>:transition` → 500，PG 报 `invalid input syntax for type uuid: "<id>:transition"`。
- **根因**：dev.controller.ts 中 `@Post('tasks/:taskId')`（saveTask）声明在 `:transition/:run/:progress/:quality/:ai-review` 之前，Express `:param` 匹配含冒号字符，动作路径先进 saveTask，taskId 带 ":transition" 后缀查库炸 22P02。既有集成测试未覆盖这几个 HTTP 动作路由（直调服务层），前端看板从未真实连通。举一反三排查：全部 controller 仅此一处裸参在冒号动作前。
- **处置**：saveTask 路由 taskId 限定 UUID 形态（`tasks/:taskId([0-9a-fA-F-]{36})`），动作路径自然落到冒号路由。HTTP 级回归已补（W-B）：dev-routes.e2e.test.ts 五个冒号动作路由对不存在任务须 404 而非 500，外加裸 saveTask 可达性。

### #19 build:run 输入未变时重跑撞唯一约束裸 500（已修为幂等）
