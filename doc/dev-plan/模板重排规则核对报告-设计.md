# 模板重排·规则核对报告前置 — 设计

> 2026-10-14 立项。缘起（用户原话）：「模板重排里是否可以先检测核对一遍再让我确定是否可以执行」
> +「另外也需要核对前面的文档已经修改的文档对后面文档的影响」。
>
> 现状：⇄ 模板重排弹窗选册相位的预检只有一个布尔启发式徽标「与模板不对版」
> （`detectSkeletonMismatch`：大章集合与模板骨架缺章/多章/顺序或章名不符任一命中即 true），
> 不告诉用户**哪里**不对版；上游滞后（CRD→PRD→设计八册）已有 `upstream-stale.ts` 派生层
> （版本 submitted_at 比较），但未进重排弹窗。
>
> 用户拍板两决策：①检测深度=**规则核对报告**（零 AI 成本秒出，不选 AI 干跑预告）；
> ②闸门语义=**报告+软闸**（规则检测只是参谋，人工拍板权不交——对版册默认不勾选仍可手动勾）。

## 1. 服务端检测升级（`template-refresh.ts`，纯函数保持可单测）

`detectSkeletonMismatch`（boolean）**退役替换**为 `auditSkeleton(content, template)` 结构化报告
（boolean 语义由 `issues.length > 0` 派生；唯一生产调用方 template-refresh.service.ts 切到新函数，
旧单测 template-refresh.test.ts 改写；`chapterTitlesOf` 保留共用不动）。三维逐项产出**人话问题行**
（`issues: string[]`，空数组=对版）：

1. **大章对照**（三段式算法，钉死防级联误报）：
   ①集合差产「缺失/多余」行（模板有文档无=缺失；文档有模板无=多余，各带章名）；
   ②对共有章（章名交集）检查相对顺序，产出「顺序错位」行；
   ③章名比对仅在位置对齐且①无缺失/多余位移时进行（①有差异时跳过③，不报连环「章名不符」）；
2. **锚点码完整性**：条目锚点正则分域钉死（权威函数 `reqSectionRule`/`designSectionRule`）——
   CRD `CR-\d+`、PRD `REQ-\d+`、设计册 `{chapter_prefix}-\d+`（单小写前缀，如 h-1/o-2；
   注意 DSG-H 是 RTM 册级锚不是条目锚，不在此列）。问题行触发条件：重复锚点码必报；
   文档有条目节但零锚点码也报一行「条目节缺锚点码」；
3. **编号规范**：`chapterTitlesOf` 为空且文档存在 `## ` 级标题 → 只报「大章编号不规范」一行
   并**跳过第 1 维**（同根因不双报）；条目节标题全量检查 `{码}-{数字} 标题` 形态 +
   编号顺连续（断号/跳号/重复各产一行）。

**上游滞后维度**（不进 auditSkeleton——它读库，非纯函数）：preflight 装配层复用
`upstream-stale.ts` 的 `reqPrdStale`/`designBooksStale`，stale 的册追加人话行
「上游 CRD 已提交 vN（本册基于 vM）——重排只动结构不动内容，建议先对话改文档同步内容再重排」。
滞后行**计入 ⚠ 问题数与明细，但不进默认勾选判定、不影响可跑判定**（仅告知——重排是结构操作，
与内容滞后正交）。CRD 无上游，`upstreamStale` 恒 false。

## 2. preflight 端点原位升级（零新端点、零新错误码）

`GET template-refresh/preflight` 每册 `mismatch: boolean | null` 升级为
`report: { issues: string[]; upstreamStale: boolean } | null`（无内容/无模板仍 null 不评）。
守卫三态（未生成/已定稿/待确认补丁）与 skip 口径不动。
前端 `RefreshPreflightItem` 接口同步升级（mismatch 字段退役）。

## 3. 前端选册相位（TemplateRefreshModal，软闸）

- 每册行尾 tag 升级：「与模板不对版」→「⚠ N 项问题」（N 含上游滞后行），点击/悬浮展开明细清单；
- 对版册显示「✓ 与模板一致」，**默认不勾选**（仍可手动勾）；
- **默认勾选判定=结构三维 issues 非空（剔除上游滞后行）且可跑**——仅上游滞后的册不默认勾
  （与滞后行「先同步内容再重排」的劝告自洽）；
- 未生成/已定稿/有待确认补丁仍硬跳过；
- 副标题措辞更新：去掉「格式启发式」，改为「规则核对明细（大章/锚点码/编号/上游滞后四维），
  最终以你的判断为准」。

破坏面：`mismatch` 字段退役的触点=api.ts RefreshPreflightItem、TemplateRefreshModal 默认勾选
与 tag 三处；仓内无现存 preflight 形态测试，零回归破坏。「report=null」实际仅由无内容触发
（resolveTemplate 对十册恒有内置模板兜底），无内容册本就硬跳过灰显，无需为该分支设计 UI。

## 4. 测试

- `auditSkeleton` 纯函数单测：三维各命中/不误报/空内容/重复锚点码/编号不规范跳过第 1 维不双报；
- preflight 集成断言升级（report 形态+上游滞后行进报）；
- 钉行为两条：上游**不**滞后时 preflight 不追加滞后行（防误报回归）；「滞后计入问题数但
  不进默认勾选判定」的断言（钉住默认勾选口径）；
- 101 回归 template-refresh 套件。

## 纪律

错误码闭集零新增；审计失败零写（preflight 只读）；console 只 warn/error；
toast kind 只 default|success|warn；样式全 var()；软闸=人工拍板权不交。
差异登记追加条目 44（待 13 册下轮基线回补 LLD-6 重排弹窗口径）。
