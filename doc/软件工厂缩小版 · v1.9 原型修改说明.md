# 软件工厂缩小版 · v1.9 原型修改说明

> 当前状态：**V1.9 隔离候选，整体验收 NO-GO。** 客户工件独立 GO，主流程健康验证及正式构建矩阵通过；最终复核发现已定稿版本被草稿改写，已按两轮规则停止当前事务路线，先审查独立草稿与不可变版本方案。完整回归与本地合入 main 尚未完成。
> 基于 v1.8 迭代；旧版本目录保持不变。

## 本轮要解决的问题

原型只有少量页面，后续任务识别和 UI 自测就没有完整的对照依据。本轮把设计完成标准落实为“需求完整覆盖、设计双向可追溯、内容相互一致”，让原型、概要设计和七册详细设计共同形成开发输入。开发执行结束后增加项目级自测及报告，报告合格后仍由用户确认转测试。

## 客户示例与实现范围

客户 UI 包含公众门户、办事申请与查询、账户、开放数据及 CMS 编辑／审核／发布。它们是客户项目工件，和 MSF 工作台自身页面分别呈现。

API 示例补齐工作流展示与允许操作字段，解释数据库 `draft/review` 状态下不同的业务展示。此为本轮已确认的示例设计修订；运行时不会自动修改或定稿上游文档。

原型仍以原生 JS 单 HTML 离线运行，状态只保留在当前页面内存，刷新恢复种子示例。客户模板、目录和任务规格作为维护源静态嵌入；客户与构建共用 pure kernel，构建以独立 renderer 生成且不读取设计 generator。执行与质量证据为明确标注的模拟结果，不代表已连接真实 AI、Git、CI、后端或通用视觉算法。

整体设计已通过独立终审，见 [设计终审](evidence/design-final-review.md)。这只允许进入实现，不等同于实现或发布通过。

## 返工记录

设计阶段进行了两轮集中修订，解决输入／输出身份、事务原子性、自动运行归属、报告分母和历史合并依据问题。历史 NO-GO 与计数更正保留在审查证据中。

客户模板首稿采用动态单页渲染；第一次修正又加入检查专用隐藏树，与实际预览形成两份结构。验收拒绝该候选，因为它可能让真实页面遗漏被隐藏标记掩盖。第二轮集中修正要求生成、交互与检查共用同一份实际业务 DOM，按可见页面和状态验证控件。

## 实现边界与审查修正

客户原型使用同一份业务 DOM 承担预览、点击和检查。客户审查第一轮的结构通过只证明页面存在；后续真实交互审查发现 CMS 角色、申请提交、登录返回与控件行为缺口，已另记完整 NO-GO，集中修正后才重新验收。

主流程审查进一步要求：上游正文语义变化不能只凭相同编号通过；字段/操作/流程不能只凭标记存在通过；模拟构建的实际内容与期望规则分离；构建 UI 随当前操作原子完成，旧异步回调不得附着到新构建。审查与反例保留在 evidence 中，最终结论仍以冻结候选证据为准。
